# FPGA 内窥镜 ISP 项目 —— 面试问题准备

> 以下问题围绕 Ti60_Demo 项目展开，涵盖 FPGA 基础、协议、图像处理、代码手写四个维度。

## 一、项目总览类

### Q1：一句话介绍你的项目
答：这是我在易灵思 Ti60 FPGA 上独立开发的一套完整内窥镜 ISP 图像处理系统，覆盖从 MIPI-CSI 传感器采集、Bayer 去马赛克、AE/AWB/降噪/消光等 ISP 管线处理、DDR3 帧缓存到多路显示输出的全链路，最终在 720P60 分辨率下实现实时显示。

### Q2：你在项目中负责了哪些部分？
答：全部独立完成。包括顶层架构设计、各时钟域划分、MIPI 收发配置、IP 核选型与例化、完整 ISP 管线（DPC/Bayer2RGB/Gamma/AE/AWB/降噪/锐化/消光）、AXI4 Master 控制器设计、DDR3 读写调度、多路显示驱动、UART 命令控制，以及综合和时序收敛。

### Q3：项目用的什么 FPGA 芯片？资源规模如何？
答：易灵思 Titanium Ti60F225，60K 逻辑单元，160 个 DSP，集成 DDR3 和 MIPI 硬核。开发板搭载 4Gbit DDR3。项目综合后使用了其中相当比例的 LUT、BRAM 和 DSP 资源。

### Q4：项目中最大的技术难点是什么？
答：两个难点。一是多时钟域管理——系统涉及 8+ 个独立时钟域，需要合理划分、用异步 FIFO 隔离、保证数据不漏不重。二是 AE/AWB 的实时 I2C 闭环——不仅要统计图像还需要实时写回传感器寄存器，时序编排比较棘手。

## 二、Verilog 语法与设计类

### Q5：`assign`、`always @(*)`、`always @(posedge clk)` 有什么区别？
答：
- `assign`：组合逻辑，持续赋值，等价于连线。
- `always @(*)`：组合逻辑块，所有输入变化时重新计算，容易产生 latch（忘记 else / 不完整 case）。
- `always @(posedge clk)`：时序逻辑，时钟上升沿触发，生成寄存器。

### Q6：`wire` 和 `reg` 什么时候用？
答：`wire` 用于组合逻辑连线、模块端口连接、`assign` 的目标。`reg` 用于 `always` 块中被赋值的变量，不一定生成寄存器（组合逻辑 always 块中的 reg 不生成寄存器）。

### Q7：什么是 blocking 和 non-blocking 赋值？各自在什么时候用？
答：
- `=`：阻塞赋值，立即执行，用于组合逻辑 `always @(*)`。
- `<=`：非阻塞赋值，所有右侧先求值，时钟沿后统一更新，用于时序逻辑 `always @(posedge clk)`。

规则：**时序用 `<=`，组合用 `=`，绝不混用。**

### Q8：什么叫 latch？如何避免？
答：latch 是电平敏感的存储单元，在组合逻辑中如果不给某个信号在所有条件下赋值就会生成。
避免方法：
- `if` 必须配 `else`
- `case` 必须配 `default`
- 所有被赋值变量在每一条执行路径上都有明确值

### Q9：`localparam` 和 `parameter` 的区别？
答：`parameter` 可被上层模块通过 `#()` 重写，`localparam` 不可被重写，仅模块内部使用。

### Q10：`generate` 语句有什么用？
答：用于条件编译和批量例化。比如我的 AXI4 控制器根据 `C_W_WIDTH` 参数不同例化不同位宽的 FIFO（`if(C_W_WIDTH==64)` 例化 W0_FIFO_64）。

## 三、跨时钟域 (CDC) 与 FIFO

### Q11：什么是亚稳态？怎么解决？
答：触发器的 setup/hold 时间不满足时，输出进入不确定的中间电平，可能导致后级电路采到错误值。
解决方法：
- 单 bit 信号：**两级同步器**（Two FF Synchronizer）
- 多 bit 总线：**异步 FIFO**（Gray 码指针 + 两级同步器）
- 带使能的多 bit 数据：DMUX 同步器

### Q12：手写一个异步 FIFO（重点，面试高概率）
口述关键点：
1. 双端口 RAM 做存储体
2. 读写指针用 **N+1 位二进制**（N 位地址 + 1 位翻折标记）
3. 指针转 **Gray 码**：`gray = bin ^ (bin >> 1)`
4. **两级同步器**将 Gray 码跨时钟域
5. 空判断：读 Gray 码 == 同步后的写 Gray 码
6. 满判断：写 Gray 码的高 2 位与同步后读 Gray 码的高 2 位相反，其余位相同

> 完整代码见项目介绍书第 10 章。

### Q13：异步 FIFO 为什么用 Gray 码而不是二进制码？
答：Gray 码相邻值只有 1 bit 变化。跨时钟域时，即使发生亚稳态，采样结果最多差 1（要么旧值要么新值），不会出现全 bit 随机跳变的错误中间值。FIFO 的满/空判断允许"保守"判断（假满/假空不影响功能，只影响吞吐），Gray 码天然满足这个要求。

### Q14：异步 FIFO 的深度怎么确定？
答：取决于写速率、读速率、最大连续写入量。
公式：`最小深度 = 最大连续写入量 - 同时段内能读出的量`
- 例：写 100MHz，连续写 80 个；读 80MHz。写 800ns，读 64 个 → 深度至少 16。
- 实际设计我会留余量，比如项目中 DDR 写入 FIFO 用了 512 深度。

### Q15：同步 FIFO 和异步 FIFO 的适用场景？
答：
- 同步 FIFO：同时钟域内流水线缓冲、位宽转换。如 ISP 管道中 3×3 行缓冲。
- 异步 FIFO：跨时钟域数据传输。如像素时钟域 → DDR 时钟域。

### Q16：两级同步器为什么能消除亚稳态？
答：第一级 FF 输出可能处于亚稳态，但经过一个完整时钟周期后进入第二级 FF 时，亚稳态的振荡幅度已经衰减到可以被正确识别的电平。两级同步器的 MTBF（平均无故障时间）在正常条件下可达数年甚至数十年。

## 四、UART 协议

### Q17：UART 协议讲一下帧格式
答：空闲高电平 → 1 起始位（低）→ 8 数据位（LSB 先发）→ 可选校验位 → 1 停止位（高）。本项目使用 460800-8-N-1。

### Q18：为什么 UART 接收要用 16 倍过采样？
答：三个原因：
1. 在 bit 中心点（第 7-8 个采样脉冲）采样，避开跳变沿，数据最稳定
2. 起始位检测后在第 8 个脉冲再次验证低电平，可过滤毛刺误触发
3. 允许收发时钟有约 5% 偏差（16×10bits 累计偏移 < 0.5bit）

### Q19：你项目中 UART 怎么同时收发和对 ISP 下达命令？
答：我的 `uart_control_top` 里例化了两个 `uart_receiver` 并行监听同一个 `fpga_rxd`。其中 receiver_0 做数据回环（接收→发送），receiver_1 将数据送给 `uart_scope` 解析为 ISP 控制命令（AE 使能、锐化使能、缩放等级等）。

### Q20：`integer_divider` 产生的是时钟还是使能脉冲？为什么？
答：产生的是使能脉冲（`divide_clken`），而不是分频时钟。FPGA 设计中不应该用逻辑生成时钟，因为会产生时钟偏斜、布线不确定性、增加 STA 复杂度。正确的做法是使用全局时钟，产生单周期使能脉冲作为"门控信号"，这是 FPGA 低功耗/多速率设计的标准范式。

## 五、AXI4 总线

### Q21：AXI4 有哪些通道？各通道的作用？
答：5 个独立通道：
- **写地址通道 (AW)**：主机→从机，含起始地址、突发长度、突发类型
- **写数据通道 (W)**：主机→从机，含数据 + WSTRB + WLAST
- **写响应通道 (B)**：从机→主机，返回写完成状态
- **读地址通道 (AR)**：主机→从机，与写地址结构相同
- **读数据通道 (R)**：从机→主机，含数据 + RRESP + RLAST

### Q22：VALID/READY 握手机制讲一下
答：
- VALID 拉高表示发送方数据有效，拉高后必须保持到 READY 握手完成
- READY 拉高表示接收方可以接收，可以在 VALID 前或后拉高
- 传输发生在 VALID 和 READY 同时为高的时钟沿
- 不同通道间的 VALID/READY 无依赖关系（AXI4 允许写数据早于写地址传输）

### Q23：AXI4 有哪些突发类型？
答：
- **FIXED**：固定地址，每次 beat 同一地址（适合 FIFO 类外设）
- **INCR**：递增地址（本项目使用，每次 +16 bytes）
- **WRAP**：到达边界后回绕（适合 Cache 行填充）

### Q24：项目中 AXI4 控制器做了哪些设计？
答：我写了一个可参数化的 `axi4_ctrl` Master 控制器：
1. 参数化位宽（C_W_WIDTH / C_R_WIDTH）适配不同数据源
2. 帧级调度：VSYNC 下降沿作为 EOF 触发帧缓冲切换
3. 4 缓冲乒乓：写指针永远不会超过读指针，避免数据覆盖
4. 跨时钟域：写侧 FIFO（像素时钟→AXI 时钟）+ 读侧 FIFO（AXI 时钟→像素时钟）

### Q25：AXI4 读/写一次突发事务的完整时序是怎样的？
答（以写为例）：
1. Master 拉高 AWVALID + 设置 AWADDR/AWLEN/AWSIZE/AWBURST
2. Slave 拉高 AWREADY → 握手完成，写地址传输
3. Master 拉高 WVALID + 发送 WDATA，每个 beat WREADY 握手
4. 最后一个 beat 时 WLAST 拉高
5. Slave 处理完毕后拉高 BVALID + BRESP
6. Master 拉高 BREADY → 写事务完成

## 六、DDR3 存储

### Q26：DDR3 为什么是"双倍数据率"？
答：DDR3 在时钟的上升沿和下降沿各传输一次数据，所以数据速率是时钟频率的 2 倍。内部采用 8n 预取架构——每个内存访问周期预取 8 个数据字，因此核心频率实际上是数据速率的 1/8。

### Q27：DDR3 关键命令和时序参数
答：
- 命令：ACT（行激活）、RD（读）、WR（写）、PRE（预充电）、REF（刷新）
- tRCD：行激活到读写延迟
- tCL（CAS Latency）：读命令到数据输出延迟
- tRP：预充电周期
- tRFC：刷新周期（约 260ns，是 DDR 操作最慢的命令）

### Q28：项目中的 DDR3 乒乓缓冲怎么做的？
答：
- `ddr_rw_ctrl`：3 缓冲，写索引循环 0→1→2→0，读索引落后写索引至少 1 帧
- `axi4_ctrl`：4 缓冲，写入指针递增时跳过读指针所在缓冲区，更安全
- 每帧结束时（VSYNC 下降沿）触发缓冲切换，同时复位读写 FIFO

### Q29：DDR 读写仲裁策略是怎样的？
答：读/写不能同时进行。我的状态机在 IDLE 状态下：
1. 优先判断写 FIFO 是否满 32 个（一个 burst 的量）→ 是 → 发起 DDR 写
2. 否则判断读 FIFO 是否未满 + 读地址未越界 → 是 → 发起 DDR 读

## 七、MIPI 协议

### Q30：MIPI-CSI 和 MIPI-DSI 的区别？
答：CSI（Camera Serial Interface）是从相机接收图像数据，DSI（Display Serial Interface）是向显示器发送图像数据。两者物理层和协议层类似（都有 HS/LP 模式、Lane 管理），但数据方向相反。我的项目同时使用了 CSI RX 和 DSI TX 两个 IP 核。

### Q31：MIPI 的 HS 和 LP 模式是什么？
答：
- **HS（High Speed）**：差分高速传输，用于大量图像数据，MIPI D-PHY 可达 1.5Gbps/Lane
- **LP（Low Power）**：单端低速传输，用于控制和低功耗状态，速率约 10Mbps

CSI RX 需要在 LP 模式下发送指令配置传感器，在 HS 模式下接收图像数据流。

## 八、ISP 图像处理

### Q32：Bayer 阵列是什么？为什么需要 Bayer2RGB？
答：图像传感器每个像素只能感知光强，需在前方加彩色滤光片（CFA）。Bayer 阵列是常见的 CFA 排列（RGGB），每个像素只记录一种颜色。Bayer2RGB 是通过插值算法为每个像素恢复缺失的两个颜色通道，生成完整 RGB 图像。

### Q33：双线性插值法的原理？
答：
- 非绿点 → G：上下左右 4 个 G 像素取平均
- 绿点 → R/B：左右或上下 2 个同色像素取平均
- 红点 → B / 蓝点 → R：四角 4 个同色像素取平均
- FPGA 实现用移位代替除法（/2 → >>1，/4 → >>2）

### Q34：AE 自动曝光的原理？
答：统计每帧图像的全局亮度均值 Y，与目标亮度 Yt 比较得到差值 ΔY。通过查表将 ΔY 映射为曝光时间步长 ΔT，下一帧曝光时间 Tn = T + ΔT。当 |ΔY| 小于阈值时认为已收敛，停止调节。灰度转换公式定点化：`Y = (77R + 150G + 29B) >> 8`。

### Q35：AWB 自动白平衡的灰度世界法原理？
答：假设自然场景中所有颜色的平均值应趋近于中性灰（R=G=B）。实现步骤：
1. 统计每帧 R/G/B 三通道各自的总和
2. 除以像素总数得到各通道均值
3. 基准值取 128（8bit 范围一半）
4. 增益系数 = 128 / 通道均值（通过 ROM 查表）
5. 每个像素各通道乘以对应增益系数

### Q36：ISP 低延迟设计的关键是什么？
答：所有处理以**行为单位**而非帧为单位。使用 Line Buffer（2~3 行 FIFO）即可实现 3×3 滑动窗口滤波，延迟仅若干行而非一整帧（~16.7ms@60fps）。行场信号需要和像素数据同步打拍。

### Q37：中值滤波和均值滤波的区别？
答：
- 均值滤波：取邻域均值，计算简单但模糊边缘，对椒盐噪声无效
- 中值滤波：取邻域中值，能有效去除椒盐噪声且保留边缘，但需要排序电路（我用 `sort3` 单元级联实现 3×3 中值排序）

### Q38：消光/高光抑制的基本流程？
答：三步：检测→压缩→补偿。
1. 通过亮度阈值 + 饱和度判断检测高光像素
2. 用 Gamma/S 型曲线查表压缩亮度
3. 用周围正常像素插值补偿纹理

## 九、时序与后端

### Q39：什么是 setup time 和 hold time？
答：
- **Setup time**：数据必须在时钟沿到达前稳定保持的最小时间
- **Hold time**：数据必须在时钟沿到达后继续保持的最小时间
- 违反 setup → 逻辑走太慢（组合路径太长）→ 降频或插入流水
- 违反 hold → 逻辑走太快（路径太短）→ 无法靠降频修复，只能插 buffer

### Q40：项目中的时序约束怎么做的？
答：用 SDC 文件定义各时钟域频率、时钟组关系（异步时钟域之间设 `set_clock_groups -asynchronous`）、I/O 延迟。综合策略选 speed 模式，布局布线选 TIMING_1 优化级别，并开启有益时钟偏斜（beneficial skew）。

### Q41：什么叫时钟偏斜（Clock Skew）？有益偏斜是什么？
答：时钟偏斜是同一时钟到达不同寄存器的时延差。如果偏斜使得源寄存器和目的寄存器的时钟采样窗口错开，且有利于满足时序，称为有益偏斜。布局布线工具可自动利用有益偏斜来修复 setup 违例。

### Q42：综合和布局布线各做了什么？
答：
- **综合**：RTL → 门级网表（LUT/FF/BRAM/DSP 映射），进行逻辑优化
- **布局**：将网表元件分配到 FPGA 的具体物理位置
- **布线**：在已布局的位置之间建立物理连线，确保满足时序约束

## 十、行为面试/综合类

### Q43：你为什么选 FPGA 而不是 ARM/GPU/DSP 来做图像处理？
答：FPGA 的优势是：
1. **确定性低延迟**：流水线处理，延迟可精确计算到时钟周期级别
2. **并行度高**：ISP 管线各阶段可同时工作，吞吐量高
3. **接口灵活**：原生支持 MIPI/LVDS/HDMI 等高速接口，无需外接桥接芯片
4. 相比于 GPU 功耗更低，对于嵌入式/便携内窥镜场景更合适
代价是开发周期更长，算法实现需要面向硬件的思维转换。

### Q44：项目中遇到什么 bug，怎么调试的？
答：修过跨时钟域数据丢失的问题——因为 VSYNC 信号的跨时钟域同步只做了一级打拍，偶尔采不到。改成两级同步器 + 电平检测（打两拍后做边沿判断）后解决。另外调试 AE 收敛速度时发现 I2C 写回速率成为瓶颈，增大了 I2C 时钟频率（从 100KHz 调到 400KHz）改善了响应速度。

### Q45：如果让你重新设计这个项目，你会改进什么？
答：三个方向：
1. 把 ISP 管线做成参数化/可配置流水线，方便模块插拔
2. 增加 3D 降噪（时域），利用帧间信息提升低光画质
3. 加入软核 CPU（RISC-V）做高层调度（ISP 参数决策、通信协议处理），FPGA 专注数据路径加速，软硬协同更灵活

### Q46：项目中用到的 Efinix IP 核，如果让你手写能写吗？
答：FIFO 类 IP 可以手写，熟练掌握了异步 FIFO 的 Gray 码 + 两级同步器设计。CSI/DSI/DDR 这类高速 PHY 涉及硬核模拟电路和时序训练，需要厂商底层支持，不适合用纯 RTL 替代。实际项目中选择合适的 IP 核是工程师的重要能力——用对轮子也是工程素养的体现。
