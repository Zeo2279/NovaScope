# AE（自动曝光）控制模块系统集成代码解析

本文档详细解析了 FPGA 图像处理系统中自动曝光（AE）模块在顶层（Top 级）的集成代码。该部分代码负责将**亮度统计**、**曝光算法**和 **I2C 寄存器实时回写**这三大模块有机结合，形成一个完整的动态闭环反馈系统。

---

## 1. 变量声明详解

代码最开始定义了连接各个子模块之间数据和控制流的连线（`wire`）与寄存器（`reg`）。

### 1.1 算法与统计相关信号
*   **`wire ae_done;`**
    *   **作用**：一帧图像统计完成的标志位。由 `isp_stat_ae` 模块在每帧图像结束时（VSYNC 边缘）产生，通知算法模块可以开始计算。
*   **`wire [31:0] ae_cnt;`**
    *   **作用**：当前帧有效统计区域内的像素总数（这里设置为整图 1280x720 像素）。
*   **`wire [31:0] ae_sum;`**
    *   **作用**：当前帧有效统计区域内所有像素的亮度（灰度）值累加总和。
*   **`wire [31:0] ae_avg;`**
    *   **作用**：图像平均亮度值（总和 / 像素数）。（注：此段代码中仅声明，实际计算可能在 `alg_ae` 内部完成）。
*   **`wire [16:0] cmos_exposure;`**
    *   **作用**：`alg_ae` 算法模块计算出的**最新曝光时间**（快门长度）。
*   **`wire [7:0] cmos_gain;`**
    *   **作用**：`alg_ae` 算法模块计算出的**最新模拟增益**（Analog Gain）。
*   **`wire [7:0] dgain;`**
    *   **作用**：数字增益参数（此段代码未将其写入 Sensor，可能用于后续 ISP 管道的内部亮度数字补偿）。
*   **`wire cmos_change_start;`**
    *   **作用**：算法计算完成标志。当算法计算出一组新的 `cmos_exposure` 和 `cmos_gain` 后拉高，请求启动 I2C 写回操作。
*   **`wire cmos_change_done = 1'b1;`**
    *   **作用**：反馈给算法模块的完成信号。这里直接赋 `1`，表示算法模块送出请求后不需要阻塞等待物理 I2C 写完，可以立刻继续后续逻辑。

### 1.2 I2C 寄存器与状态机控制信号
*   **`reg cmos_change_start_dly;`**
    *   **作用**：用于对 `cmos_change_start` 信号打拍存一拍，用于状态机中检测该信号的边沿（代码中 `~cmos_change_start & cmos_change_start_dly` 检测的是下降沿）。
*   **`wire [15:0] ae_exposure` / `wire [7:0] ae_gain;`**
    *   **作用**：为了方便后续切片操作，将算法输出的参数重新用别名连接。
*   **`reg [15:0] update_addr;`**
    *   **作用**：当前状态机要写入的 Sensor 内部 I2C 寄存器地址（如 0x3048）。
*   **`reg [7:0] update_data;`**
    *   **作用**：当前状态机要写入 Sensor 的具体数值。
*   **`reg update_valid;`**
    *   **作用**：写数据有效使能信号，拉高时通知底层 `i2c_timing_ctrl_16bit` 去执行物理总线写入。
*   **`wire config_busy;`**
    *   **作用**：指示 I2C 配置正在进行中，等于 `update_valid`。
*   **`wire config_done;`**
    *   **作用**：底部 I2C 模块反馈的一次配置完成信号。
*   **`wire i2c_transfer_complete;`**
    *   **作用**：底层 I2C 单次字节传输彻底完成的标志位。
*   **`reg i2c_transfer_complete_dly;`**
    *   **作用**：对 `i2c_transfer_complete` 打拍，用于检测上升沿，准确捕获“刚完成”的瞬间。
*   **`reg [1:0] update_state;`**
    *   **作用**：写入控制状态机的当前状态寄存器。
*   **`reg update_state_set_data;`**
    *   **作用**：一个状态标志，防止在同一个状态内重复赋地址和数据，确保 `update_valid` 只被触发一次。

### 1.3 超时控制变量
*   **`localparam TIMEOUT_COUNT = 32'd192000;`**
    *   **作用**：超时阈值。由于使用 96MHz 时钟，192000 个周期约等于 2 毫秒。
*   **`reg [32:0] timeout_counter;` / `reg timeout_enabled;`**
    *   **作用**：超时计数器及其使能开关。如果 I2C 从设备没响应导致卡死，计数器达到阈值后能强制状态机跳转，防止总线死锁。

### 1.4 总线复用与底层接口信号
*   **`wire ae_i2c_sda_o;` / `wire ae_i2c_sda_oe;`**
    *   **作用**：AE 的 I2C 时序模块独立生成的 SDA 输出数据和 SDA 输出使能信号。

## 2. 核心模块实例化解析

### 2.1 `isp_stat_ae` (亮度统计)
这个模块相当于整个 AE 系统的“眼睛”。
*   输入视频流 `crop_valid`, `crop_vsync`, `crop_data`。
*   使用 `.rect_w(12'd1280), .rect_h(12'd720)` 设定了统计区域为全局图像。
*   每帧结束时，计算出当前帧的总亮度 `ae_sum` 和像素数 `ae_cnt` 并发出 `ae_done`。

### 2.2 `alg_ae` (AE核心算法)
相当于 AE 系统的“大脑”。
*   接收 `ae_sum`、`ae_cnt` 以及 `ae_done` 触发。
*   目标亮度设定为 `8'd30+scale_level`（说明目标亮度受外部缩放等级或 UI 控制调节）。
*   内部通过比较当前均值和目标值，计算出新的 `cmos_exposure` 和 `cmos_gain`，并通过 `cmos_change_start` 下发更新命令。

## 3. I2C 更新状态机分析

这段 `always` 块是一个典型的多步写入状态机。因为算出来的是 16 位曝光和 8 位增益，而 Sensor 的寄存器宽度是 8 位的，所以需要拆分成 3 次独立的 I2C 操作：
1.  **`UPDATE_IDLE`**：等待 `cmos_change_start` 边沿信号。一旦触发，将要写的最低 8 位曝光数据（`ae_exposure[7:0]`）和地址（`0x3048`）准备好，进入下一个状态。
2.  **`UPDATE_EXP_LOW`**：拉高 `update_valid`。等待底层 I2C 返回 `i2c_transfer_complete`（或超时），成功后进入写高 8 位状态。
3.  **`UPDATE_EXP_HIGH`**：更新地址为 `0x3049`，数据为 `ae_exposure[15:8]`。再次拉高 `update_valid` 等待完成，然后进入写增益状态。
4.  **`UPDATE_GAIN`**：更新地址为 `0x3110`，数据为 `ae_gain`。完成后回到 `UPDATE_IDLE`，完成一轮彻底的 AE 参数闭环更新。

**超时机制的加入（`timeout_counter`）是这段代码非常严谨的设计亮点**。在硬件通信中，如果没有超时强切机制，一旦 Sensor 由于某种原因未发回 ACK 或者总线受干扰，状态机就会永久停留在某个状态，导致后续帧的 AE 彻底失效。

## 4. I2C 总线共享逻辑解析

```verilog
assign csi_sda_o = ae_enable?(sc130_i2c_sda_o & ae_i2c_sda_o):sc130_i2c_sda_o;
assign csi_sda_oe = ae_enable?(sc130_i2c_sda_oe | ae_i2c_sda_oe):sc130_i2c_sda_oe;
assign csi_scl_o = ae_enable?(sc130_i2c_scl_o & ae_i2c_scl_o):sc130_i2c_scl_o;
```

这段逻辑非常经典。在一个系统中通常只有一对物理 I2C 管脚连到 CMOS，但在 FPGA 内部：
1.  上电初始化时，有一个“初始化 I2C 控制器”在往外发数据（`sc130_...`）。
2.  运行过程中，你的“AE I2C 实时控制器”也在往外发数据（`ae_i2c_...`）。

为了让两套控制器安全地共用物理管脚：
*   **SDA / SCL 输出（`_o`）采用“线与（&）”逻辑**：因为 I2C 总线是开漏（Open-Drain）架构，默认高电平，只要有一个模块想拉低总线，总线就被拉低。
*   **使能信号（`_oe`）采用“或（|）”逻辑**：只要“初始化模块”或“AE 模块”中任何一个要求取得总线控制权，整体三态门的使能就会被打开。
*   **总开关**：使用顶层的 `ae_enable` 开关控制，当 AE 不使能时，完全屏蔽 AE 模块对总线的干扰。

### 5. `i2c_timing_ctrl_16bit` 底层驱动
接收上方状态机拼好的 `{8'h6a, update_addr, update_data}` 24 位数据。其中 `8'h6a` 是 CMOS 传感器的 I2C 器件地址（Device ID）。它以 `96MHz` 为驱动时钟，将 I2C 时序降频至标准 `400KHz` 传输。

## 6. AE 模块整体时序逻辑深度解析

在自动曝光 (AE) 的闭环控制系统中，时序逻辑的严谨性决定了画面是否会出现闪烁、撕裂或曝光延迟。结合代码分析，整个 AE 系统的时序严格按照视频流的同步信号进行流转，主要分为以下三个关键阶段：

### 6.1 第一阶段：亮度统计 (isp_stat_ae) —— 发生在一帧有效图像传输期间
*   **触发与执行时机**：当一帧图像的像素数据伴随着有效数据使能信号（如 `crop_valid` 或 `href`）源源不断地输入时，亮度统计模块在像素时钟（`pclk`）的驱动下，**实时、逐个像素**地累加有效区域内的亮度值（`ae_sum`）和计数像素个数（`ae_cnt`）。
*   **完成时机**：当一帧图像的最后一个有效像素传输完毕（通常由垂直同步信号 `vsync` 的下降沿、`frame_end` 标志或计数值达到设定边界来判断），本帧的统计工作正式完成。此时，统计模块会输出最终的统计结果并拉高完成标志位（如 `ae_done`）。
*   **时序特征**：这是一个长周期的累加过程，贯穿于整帧可见图像的传输周期中。

### 6.2 第二阶段：亮度控制与算法计算 (alg_ae) —— 发生在帧间消隐区 (VBLANK) 开始时
*   **触发时机**：算法模块在接收到统计模块的完成标志（`ae_done`）或者检测到新一帧即将开始的帧起始信号（如代码中的 `frame_start`）时被唤醒。
*   **计算过程**：在消隐区（VBLANK）刚开始的几个时钟周期内，算法模块利用上一步得到的亮度总和与像素总数，计算出当前画面的平均亮度，并与预设的目标亮度进行比对。通过内部的状态机、PID 控制或者预设好的步长查找表（LUT），快速计算出下一帧所需要的**目标曝光时间**（`target_exposure`）和**目标增益**（`target_gain`）。
*   **输出信号触发**：算法模块同时会检测底层 I2C 接口是否处于空闲状态（通过检查 `!cmos_change_done` 盲区标志）。当新参数计算完毕且总线空闲时，算法模块会在 `frame_start` 有效时（即新一帧开始的绝佳时机），将 `cmos_change_start` 信号拉高一个时钟周期：
    ```verilog
    else if (frame_start) begin
        cmos_change_start <= 1; // 触发底层I2C更新配置
    end
    ```
*   **时序特征**：控制算法的计算纯粹是组合逻辑或极短周期（几个 `pclk` 周期）的串行状态机计算，速度极快。**参数的生效（锁存）必须安排在帧间消隐区（VBLANK）进行**，这是为了保证曝光参数的切换在画面之外，防止同一帧画面中途突然变亮或变暗（即所谓的“画面割裂”效应）。

### 6.3 第三阶段：I2C 数据传输 (i2c_realtime_writer) —— 发生并在消隐区内完成
*   **触发时机**：顶层的 I2C 写入状态机一直在轮询监控。一旦捕捉到 `cmos_change_start` 的边沿跳变，状态机立刻从空闲状态（`UPDATE_IDLE`）进入工作流。
*   **传输时序**：
    1.  状态机按照预定的顺序，依次发起 3 次独立的 I2C 写操作：先写曝光时间低 8 位 -> 再写曝光时间高 8 位 -> 最后写模拟增益 8 位。
    2.  每一步操作时，拉高 `update_valid`，将准备好的寄存器地址和数据喂给底层的 `i2c_timing_ctrl_16bit` 驱动模块。
    3.  底层驱动模块利用内部高频时钟（如 96MHz）降频，生成符合标准 I2C 协议的 400KHz SCL 时钟，将数据按照 `起始位 -> 器件地址 -> 寄存器地址 -> 数据 -> 停止位` 的串行时序打出。
    4.  每写完一个寄存器，底层通过 `i2c_transfer_complete` 反馈给顶层状态机，状态机再推进到下一个寄存器的写入。
*   **时间要求与防冲突**：
    *   3 次 8 位有效数据的 I2C 写入（加上协议本身的开销），总计耗时约在几百微秒（us）级别。而通常图像传感器的 VBLANK 时间也在毫秒（ms）或大几百微秒级别。因此，只要保证 VBLANK 的持续时间略大于 I2C 传输时间，就能确保在新的一帧的第一行像素开始曝光前，新的配置已经全部写入 CMOS 传感器并被锁存生效。
    *   状态机内部严格的握手机制和 `timeout_counter` 超时机制，确保了 I2C 传输过程的时序安全。如果因干扰导致传感器没有回 ACK 或者总线拉死，系统也会在超时后强行结束写入状态机，避免把传输拖延到下一帧的有效图像区域。
