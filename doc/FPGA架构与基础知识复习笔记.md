# FPGA 架构与数字 IC 基础知识复习笔记

这份笔记整理了关于 NovaScope 图像处理系统架构及底层 FPGA/IC 设计核心概念的深入讨论。非常适合在面试前进行突击复习。

---

## 1. 图像带宽膨胀：为什么 RAW 到 RGB 变大 3 倍？
*   **RAW 数据（传感器原始输出）：** 每个像素经过 Bayer 滤光片，只能感知一种颜色（R/G/B 之一）。因此每个像素只需 **1 份数据**（例如 8-bit RAW 对应 1 Byte）。
*   **RGB 数据（ISP 去马赛克后）：** 经过插值计算，每个像素补齐了另外两种颜色，变成了完整的全彩像素。以 RGB888 为例，每个像素包含 R、G、B 共 **3 份数据**（即 3 Bytes）。
*   **结论：** 像素总量不变，但单像素信息量扩充为 3 倍，所以处理后的总带宽膨胀为原来的 3 倍。

## 2. 存储调度：半双工的 DDR 为什么能“同时”读写？
*   **物理层是半双工的：** DDR 的数据引脚在同一周期只能读或只能写。
*   **宏观“同时”的秘密（分时复用 TDM）：**
    1.  **大容量异步 FIFO：** ISP 写数据和显示器读数据，都不是直接找 DDR，而是找各自专属的 FIFO 缓冲池。
    2.  **大带宽碾压与突发（Burst）：** DDR 带宽远大于单路业务需求。仲裁器先让 DDR 极高速地 Burst 写入一波 ISP 数据，然后再花极短的时间切方向，Burst 读出一波数据喂给显示 FIFO。
    3.  **不断流：** 只要切换得足够快，FIFO 不溢出也不读空，外围设备就“感觉”自己在独占带宽同时工作。

## 3. AXI 总线的作用与核心机制
**AXI 就像芯片内部的高速公路和物流中枢**，用来替代点对点杂乱的连线，提供标准化的高性能数据搬运。

*   **五大独立通道：** 写地址、写数据、写响应、读地址、读数据通道完全分离，支持全双工。
*   **VALID/READY 双向握手：**
    *   发送方准备好发：`VALID = 1`
    *   接收方准备好收：`READY = 1`
    *   **只有当两者同时为 1（同频上升沿），才表示数据成功交接 1 次。**
*   **代码中的反压机制：**
    *   `assign w_wfifo_ren = axi_wvalid && axi_wready;`
    *   只有 AXI 总线成功把数据握手送出后，才从内部 FIFO 读出下一个旧数据。如果下游忙 (`ready=0`)，FIFO 停止吐数，数据积压在上游，这叫反压（Back-Pressure），确保一个像素都不丢。

## 4. AXI 互联网络与三大版本
*   **AXI Interconnect（互联矩阵）：** 是一个物理存在的 IP 核，里面包含了复杂的路由多路复用器（MUX）和决定谁先谁后的**仲裁器（Arbiter）**。
*   **三个版本各司其职：**
    1.  **AXI4 Full（全功能）：** 支持极长的 Burst 突发，用于连接 DDR、BRAM 等做大块数据的高速搬运。
    2.  **AXI4-Lite（轻量级）：** 不支持 Burst，用于配置低速寄存器（如 PC 调参、CPU 配置外设）。
    3.  **AXI4-Stream（数据流）：** 没有地址线，只有数据和握手，用于 MIPI 到 ISP、ISP 各模块间的点对点高速纯数据流传输。

## 5. DDR 带宽计算与 60% 效率折损
*   **理论峰值带宽：** 400MHz 时钟的 16-bit DDR3。
    `400MHz × 2 (双边沿) = 800 MT/s`
    `800 MT/s × 2 Byte (16-bit) = 1.6 GB/s`
*   **实际可用效率（约 60%）：** 为什么达不到峰值？
    1.  **读写切换开销（Turnaround）：** 半双工总线频繁换向必须插入空闲周期防撞车。
    2.  **行激活/预充电（Activate/Precharge）：** DDR 切银行/换行读写需要极大的等待开销。
    3.  **周期性刷新（Refresh）：** DRAM 电容漏电，需定时停工充电。
*   **实际可用：** 1.6 GB/s × 60% ≈ 960 MB/s。能够覆盖 1080P60 读写所需的 700~800 MB/s。

## 6. 带权重的轮询调度（Weighted Round-Robin）
*   **为什么不用普通轮询（绝对公平）？** 图像显示对数据断流极度敏感，晚一拍画面就会撕裂或黑屏（Underflow）；而 ISP 写稍晚一点顶多在 FIFO 积压。
*   **带权重调度：** 给关键模块（显示读）分配高权重（如允许连续突发 3 次），给非关键模块（如 CPU、ISP写）分配低权重（连续 1 次）。在总线冲突抢夺时，保证屏幕永远不缺数据。

## 7. 时钟域：为什么不全局用一个最高时钟（GALS架构）？
即使有 FIFO，芯片也**绝不能**全局统一跑 DDR 的 400MHz 最高时钟，原因：
1.  **时序收敛无解：** 复杂的 ISP 乘法逻辑无法在 2.5ns 内跑完，会引发无法布线的时序违例。
2.  **功耗爆炸：** $P \propto f \cdot C \cdot V^2$，全芯片高频翻转会发热烧毁。
3.  **物理接口死板：** MIPI 和 HDMI 外设强制要求特定的输入/输出时钟（如像素时钟 148.5MHz），不能瞎快。
4.  因此采用 **全局异步，局部同步 (GALS)** 架构：各个模块跑自己最舒服的时钟，中间用异步 FIFO 过渡。

## 8. AE 控制：闭环延迟 vs 防止画面闪烁
*   **闭环延迟（物理滞后）：** 从“环境光变化” $\rightarrow$ “ISP统计” $\rightarrow$ “I2C下发寄存器” $\rightarrow$ “CMOS 下一帧生效”，客观上必定存在 **2~3帧的时间差**。
*   **防闪烁处理（算法逻辑）：**
    *   **步长限制（阻尼）：** 因为知道有延迟，所以算出需要大幅调光时，代码中强行限制**单帧只允许调节 ±12.5%**（`gain0` 钳位）。
    *   **等待与同步：** 在场消隐区（VBLANK）下发 I2C。小步快跑、平滑过渡，防止系统因为闭环延迟而发生过度补偿（过亮/过暗疯狂震荡）。

## 9. 位宽匹配：16-bit DDR 为什么配 128-bit AXI？
这是一个典型的**“齿轮箱（Gearbox / 降频拓宽）”**设计：
*   **DDR 物理侧（窄且快）：** 16-bit @ 800 MT/s $\rightarrow$ 1.6 GB/s。
*   **FPGA 内部侧（宽且慢）：** 内部逻辑跑不上 800MHz，所以 DDR 控制器硬核将连续收到的 8 个 16-bit 数据拼成一个 128-bit 数据包。
*   **内部 AXI 总线：** 128-bit @ 100 MHz $\rightarrow$ 1.6 GB/s。
*   这样两边总带宽相等，完美承接高速数据流。

## 10. FIFO 与 IP 核使用的工程经验
*   **不要手写异步 FIFO：** 同步 FIFO 简单，但跨时钟域的异步 FIFO 涉及亚稳态、格雷码转换和复杂的时序约束。自己写极易出极难复现的隐蔽 Bug，**工程中永远优先调用厂家成熟验证过的 IP 核**。
*   **底层的 BRAM 优势：** 厂家 IP 会智能调用 FPGA 内部的物理硬核存储块（BRAM），零逻辑资源（LUT）占用且运行极快。
*   **名字不同的原因：** 很多厂商的 GUI 配置工具不支持代码参数化传递，生成不同位宽和深度的 IP 只能另存为不同文件（如 `W0_FIFO_64`），再用 Verilog `generate` 例化。

## 11. FPGA 底层细胞：BRAM / DDR 与 DSP / LUT 的关系
*   **BRAM vs DDR (存储器)：**
    *   **DDR (郊区大仓库)：** 芯片外部，海量存储（存整帧图像），高延迟，大家挤总线。
    *   **BRAM (桌边小抽屉)：** FPGA 内部 SRAM，容量极小（几MB），但延迟极低（1周期），百路并行。**必须用作 ISP 行缓存和 FIFO 底层**，用于实时像素流转。
*   **DSP vs LUT (计算器)：**
    *   **LUT (万能积木/软逻辑)：** FPGA 最基本逻辑单元，用它拼乘法器耗资源、功耗高、跑得慢。常用来做控制逻辑、状态机。
    *   **DSP (硬核计算器)：** 芯片中植入的专用于乘累加运算（$A \times B + C$）的物理硅片电路。综合软件会把复杂的滤波、矩阵乘法自动映射到 DSP 块上，实现 1 时钟周期出结果，极大地解放 LUT 资源。
